3. C0 CORE — EXACT MECHANISM DETAIL
============================================================


3.1 Daily volatility ruler


The core grid DOES NOT use a 5-bar intraday ATR.


ATR5_daily is a causal DAILY/session ruler:
- use the previous five COMPLETED eligible daily/session true ranges;
- shift the series so current-day final information cannot leak into the current session;
- average those five prior completed true ranges.


Define:


g = ATR5_daily / 5


This grid step g is the principal spacing unit for C0.


A Pine port must be extremely careful with daily request.security semantics:
- no lookahead;
- only prior completed daily/session information may influence the current session;
- early closes / incomplete sessions / source-readiness rules matter in the original research package.


3.2 Core inventory


- Six logical core slots/units maximum.
- Under S0 each logical unit is allocated roughly shared_budget/6.
- Share quantity is determined from the unit allocation, eligible price, integer-share rounding, and the authoritative cost model.
- Cash, existing/pending commitments, shared-cap authority and any current core cap must pass before a bid is admitted.


3.3 Session anchor


At a new observed RTH session:


anchor = observed session Open


At the end of each observed 1m bar, once bar processing is complete:


if there are NO active core lots:
    anchor = current completed Close
else:
    anchor = max(previous anchor, current completed High)


Interpretation:
- flat core follows the last completed Close;
- once core inventory exists, the anchor ratchets upward with observed Highs and does not simply follow price downward;
- session reset to Open is an important exception to the simple “flat close / holding ratchet” description.


3.4 Desired core buy levels


For the six logical grid ranks:


level_k = tick_round_down(anchor - k*g), k = 1..6


The historical C0 implementation then removes the leading ranks according to current active core occupancy. In the pinned code this is effectively:


levels = [anchor-g, anchor-2g, ..., anchor-6g][number_of_active_core_lots:]


followed by tick rounding, duplicate removal, quantity sizing and capital admission.


Do not replace this with:
- six market buys at current price;
- ATR of intraday bars;
- an average-entry-centered grid;
- unlimited DCA.


3.5 Core bid activation / fill economics in the historical OHLC engine


Archived baseline behavior forms desired core bids at each 1m decision boundary. Later REST research adds an explicit working-order lifecycle, but the economic C0 reference remains a resting/eligible buy-level concept.


Historical OHLC fill convention:
- if bar Open <= active buy limit, fill at Open;
- otherwise, if bar Low <= active buy limit, fill at the limit price;
- if neither happens, no fill.


This is an OHLC backtest convention, not proof of real exchange queue priority.


Important Pine portability issue:
- TradingView’s broker emulator may resolve same-bar limit-touch ordering differently from the Python authority.
- The pinned Python lifecycle explicitly tracks buy/sell touch ambiguity and has an archived SELL-FIRST convention in ambiguous cases.
- Therefore exact Pine Strategy Tester PnL may diverge even if signal/level logic is correct. A proper port should first compare generated levels, state transitions and intended targets, then separately compare emulator fills.


3.6 Core sell reference and rebound reduction


The ordinary core sell reference is NOT simply average entry price.


General target:


core_sell_target = tick_round_up(sell_ref + 2*g)


When a core buy is filled, the engine updates sell_ref from the filled core path; the deepest fill in the processed set becomes the relevant sell reference for that transition.


When price reaches the sell target:
- the HIGHEST-COST active core lot is the lot selected for reduction;
- if current bar Open is already at/above target, the historical engine sells at Open;
- otherwise, if bar High reaches target, it sells at the target under the OHLC convention;
- a reduction may realize a loss relative to that selected lot or to account average cost. Do not impose a “only sell above average entry” rule.


After a normal core SELL, if core inventory remains, the Python reference advances to that sell target; if core becomes flat, sell_ref becomes empty/NaN. Timeout/cap paths can reset sell_ref from remaining inventory according to code-defined rules.


3.7 Core lot expiry


The archived C0 core has a ten-trading-session lot-age rule.
- A core lot reaching the frozen age boundary is liquidated under the strategy’s TIMEOUT semantics near the session boundary.
- Do not convert this to ten calendar days.
- Gap/resume handling is policy-sensitive in the research engine; do not invent a new forced-gap rule in Pine if the exact deployed policy does not specify it.


3.8 Core cap reductions


At a completed/open processing boundary, if actual core+mini exposure or core-only exposure exceeds the frozen shared/core authority:
- the engine reduces the HIGHEST-COST core lot first;
- for C0 this is a full-tranche cap reduction, rather than silently resizing every lot pro-rata.


This is a risk/capital action, not an alpha exit.

4. G0/E1 MINI — FAVORABLE ARCHIVED MECHANISM
============================================================


The favorable archived combined branch is described as:


5m IMMEDIATE grouped 2-of-4
+ completed 65m DECLINE_DECELERATION context
+ slow exit enabled
+ N3 / BOTH / E2 / TROUGH / FIXED

This is NOT the earlier prototype that required COMPOSITE confirmation for every starter.


4.1 Fast 5m grouped depression features


Build ONLY from completed 5m aggregates. The pinned feature implementation defines four grouped depression families:


A — oscillator exhaustion
- RSI length 2 using Pine/Wilder-style RMA gain/loss construction.
- A = RSI2 < 21.


B — price displacement
- basis = SMA(Close, 23)
- sd = population-style rolling stdev over 23
- B = Close < basis - 2*sd.


C — negative-return shock
- typical = (High + Low + Close) / 3
- ROC27 = 100 * (typical / typical[27] - 1)
- z = (ROC27 - rolling_mean_55(ROC27)) / rolling_std_55(ROC27)
- C = z < -1.6.


D — structural discount
- prior completed daily/session pivot = (High + Low + Close) / 3
- structural_discount = prior pivot - 0.25*(prior High - prior Low)
- D = current 5m Close < structural_discount.


Known/readiness guard requires the completed aggregate and all required warmups/features to be valid, including RSI, Bollinger deviation, shock z-score, structural level, ATR14>0, EMA20 and CLV.


Score:


score = A + B + C + D


grouped depression qualifies when score >= 2 and feature state is KNOWN.


The grouped evidence is deliberately not described as four independent alphas; the features can be correlated.


4.2 Supporting fast features


On completed 5m bars:


TURN = Close > previous Close
RECLAIM = Close > previous High
CLV = (Close-Low)/(High-Low)
COMPOSITE = (Close > Open)
            AND TURN
            AND (RSI2 > previous RSI2)
            AND (CLV >= 0.65)


Fresh variants fire only on a false->true transition, not every bar while the condition stays true.


soft_down = Close < previous Close < Close[2]


Fast EMA20 and ATR14 are also computed on the completed 5m aggregate. The mini campaign locks original_atr from the causal fast state when the campaign is created.


4.3 Arm creation / IMMEDIATE starter event


The cohort generator requires:
- score >= 2;
- KNOWN fast state;
- a fresh-enough event separation (the historical cohort logic uses a minimum false-run and arm spacing so one continuing depression is not emitted every bar).


In the favorable IMMEDIATE variant, the qualifying grouped event confirms immediately on that completed 5m decision bar. There is no extra COMPOSITE confirmation requirement for the starter.


The exact cohort implementation also prevents continuous duplicate arms through its false-run / prior-arm spacing state. Preserve that behavior rather than treating every score>=2 bar as a fresh campaign.


4.4 Completed 65m DECLINE_DECELERATION context


The favorable branch uses completed 65m context as an admission layer.


On completed 65m bars compute:
- EMA20
- ATR14
- rolling High20 / Low20
- slope = EMA20 - EMA20[3]
- d3 = Close - Close[3]
- dprev = Close[3] - Close[6]


Define decline:


Close < EMA20
AND d3 < 0
AND dprev < 0


Then:


DECLINE_DECELERATION = decline AND d3 > dprev
DECLINE_ACCELERATION = decline AND d3 <= dprev


Since both d3 and dprev are negative, d3>dprev means the most recent 3-bar decline is still negative but less negative than the preceding 3-bar decline: selling is decelerating.


Only completed/causally available 65m context may be used. No current incomplete 65m lookahead.


The same slow table exposes an EMA20 target used by the slow-exit branch.


4.5 Campaign state machine


Conceptual mini states:


ARMED
-> BUILDING / ADD_BLOCKED
-> DERISK
-> CLOSED


Economic entry roles:
- STARTER
- DIP
- RECOVERY


Important invariants:
- first entry counts as one lifetime economic entry;
- partial-fill fragments do not create new economic entry IDs;
- once any reduction begins, reduction_started becomes true, state becomes DERISK, pending entry is cancelled, and NO NEW ADD is allowed for that campaign.


4.6 Mini size / campaign locking


Under S0:
- total mini authority = $10,000;
- N3 means three economic entry units, so nominal locked unit authority is approximately $10,000/3 before integer share rounding/cost reserve;
- the $10,000 sits inside the shared $80,000 cap.


At campaign creation, the engine locks campaign-level quantities such as:
- original ATR
- campaign budget
- per-entry unit budget
- risk authority
- original scale/equity cutoff
- initial/slow decision target


A losing campaign does not automatically receive more budget because account equity later grows.


4.7 STARTER execution


When a fresh eligible arm appears while no mini campaign exists:
- no same-minute sell conflict;
- valid RTH entry window;
- completed 65m permission/context is allowed;
- capital/equity authority is valid;


create the campaign and plan role=STARTER.


The archived economic entry contract is NEXT EXECUTABLE OPEN.


The decision Close may be stored as an intent/reference level for sizing/telemetry, but that does NOT make the entry a resting limit at the signal Close.


Pine translation concept:
completed causal signal -> next executable bar Open market-style backtest entry.


4.8 ADD timing


For tf=5 and the frozen non-clock branch:


minimum spacing = 3 * tf = 15 minutes


between economic entry decisions/fills.


For N3 + BOTH:
- total lifetime entries <= 3;
- one slot is STARTER;
- reserve_recovery = 1;
- therefore at most one DIP and at most one RECOVERY are available in the typical three-entry campaign.


4.9 DIP add


DIP requires:
- campaign already has inventory;
- no pending entry;
- no reduction has started;
- lifetime entry count below N3;
- minimum spacing satisfied;
- new/fresh grouped arm is present;
- DIP role capacity remains;
- current causal fast Close <= last mini fill/entry price - 0.5 * original_ATR;
- context/capital/time gates pass.


Then plan one DIP unit for the next executable Open.


4.10 RECOVERY add


RECOVERY requires:
- campaign already has inventory;
- no reduction has started;
- lifetime entry count below N3;
- minimum spacing satisfied;
- fresh COMPOSITE event;
- RECOVERY role capacity remains;
- current causal Close >= last mini price + 0.25 * original_ATR;
- target room remains: EMA20 - current Close >= 0.5 * original_ATR;
- context/capital/time gates pass.


Then plan one RECOVERY unit for next executable Open.


Interpretation: RECOVERY is not another dip. It adds only after price has improved enough from the last mini entry while still leaving sufficient distance to the fast mean.

5. G0/E1 MINI EXIT / REDUCTION LOGIC
============================================================


The mini has multiple exit layers. They are not interchangeable.


5.1 Risk flag / campaign loss trigger


The engine tracks campaign PnL including current inventory and costs.


Under S0, risk authority is $250.


When campaign marked PnL at a causal boundary reaches <= -risk_limit, the campaign risk flag is set and pending entry is cancelled. The next processing path gives RISK exit priority.


This is not a guaranteed maximum realized loss because price can gap/move before execution.


5.2 Absolute time exit


For the combined mini branch, nominal maximum age is:


min(first filled mini entry time + 360 wall minutes,
    scheduled RTH close - final safety minute)


When that deadline is reached, TIME exit takes priority.


Do not reset the age because of later DIP/RECOVERY entries.


5.3 Catastrophic exit — E2


For E2:


if causal fast Close <= first_price - 3 * original_ATR:
    full campaign exit = CATASTROPHIC


The first mini fill price and original ATR remain the campaign references.


5.4 Soft reduction — E2


Only once per campaign while soft_done=false:


SOFT fires if either:


A) causal fast Close < first_price - 1 * original_ATR


OR


B) mini utilization >= 0.5
   AND soft_down is true
   where soft_down = Close < previous Close < Close[2]


SOFT sells approximately 1/3 of current mini quantity, marks soft_done=true, and moves the campaign into ADD_BLOCKED/derisk behavior.


5.5 TROUGH rebound reduction — FIXED


The tested TROUGH reference is explicitly capable of reducing below average entry price.


Fixed rebound threshold:


threshold = 0.75 * original_ATR


Track prior observed campaign trough. Required rebound level is approximately:


trough + 0.75*original_ATR


but if a prior rebound reduction has already fired, a rearm_level can make the next required level higher:


required = max(trough + 0.75*ATR, prior rearm_level)


When the causal Close crosses the required rebound level:
- sell approximately 1/3 of current mini quantity;
- record the decision trough/close;
- set new rearm_level = current Close + 0.75*original_ATR.


Therefore the rule does NOT freely move the trigger lower every time a new trough appears after a reduction. This is important for parity.


5.6 Slow mean exit — completed 65m branch


The favorable branch has slow_exit enabled.


Fast risk / catastrophic / soft / rebound logic retains priority.


If none of those fires, and a completed/known 65m slow target exists, the engine evaluates recovery to the slow target on the 1m execution clock using causally available prior close information.


Conceptually:


if previous completed 1m Close >= current causally known 65m EMA20 target:
    full exit = SLOW_MEAN


The slow target is derived only from completed 65m context; no incomplete HTF lookahead.


5.7 Cap exit


If mini exposure exceeds its locked mini budget or the shared $80k authority at the relevant boundary, the risk/capital layer can perform a CAP exit/reduction. This is a capital-governor action, not an alpha signal.


5.8 Exit execution and state


Any first reduction sets:
- reduction_started = true
- state = DERISK
- pending mini buy = cancelled


No additional DIP/RECOVERY is allowed afterward.


When all mini lots are gone:
- campaign state closes;
- realized PnL/fees and campaign metadata are finalized.

1. recover/missing-data / preexisting RISK or TIME state;

8. CURRENT PRODUCTION IMPLEMENTATION VS A PINE PORT
============================================================


The current local production/research engine is fill-aware and stateful. On restart it reconstructs SOXL strategy state from durable completed bars and execution inputs. This is why current owner restarts can spend substantial time in FillAwareStrategyProvider recovery.


A Pine port could reduce local signal-state reconstruction only if Pine becomes the authoritative strategy-state/signal calculator. That does NOT automatically mean Pine should own actual broker fill/account truth.


Preferred separation to test:


TradingView Pine
- compute causal C0/G0/E1 signal/state
- emit strategy target / ENTRY / REDUCE / EXIT events


GridMax
- authenticate/dedup/persist
- maintain actual broker/fill ownership
- risk/capital/reconciliation
- price/quote safety
- SharedExecutionOwner


IBKR
- actual order/fill/position/account truth


Key challenge:
- C0 is not a simple single-position strategy. It has six logical core units, resting limit levels, highest-cost reductions, dynamic sell_ref, cap/age rules, plus a mini campaign sharing capital.
- Pine Strategy Tester has its own broker emulator and may not reproduce Python intrabar ordering exactly.
- A live Pine strategy also does not automatically receive actual IBKR fills back into its internal strategy.position state.


Therefore “Pine works” should mean causal state/signal parity first, not merely similar cumulative PnL.
